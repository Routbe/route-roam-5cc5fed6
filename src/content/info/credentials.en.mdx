# Credentials

Badges, certificates, and diplomas: origin, meaning, and visibility.

<Callout type="info" title="What exists now">
The source code includes storage rules and public display for app credentials. An external issuance API and complete acceptance controls are not yet available as a verified service.
</Callout>

## A dedicated section per app

On a public profile, published credentials can be grouped under the name of the app. This keeps the origin of a diploma, certificate, or badge recognizable. Open an item for the description and the issuer's profile, if available.

| Type | Statement by the issuer | No automatic guarantee |
| --- | --- | --- |
| Badge | For example, participation or membership | Official identity verification |
| Certificate | For example, a completed training course | Recognized accreditation |
| Diploma | For example, an earned qualification | Validity for a regulated profession |

## Publishing is a separate choice

A received item doesn't automatically belong on the web. The public projection requires acceptance, a public profile, a published app section, and active app consent. Revoked items remain excluded from the public view. A badge next to your name also has a separate display setting.

When an app is hidden, that applies to all credentials in that section. A public screenshot cannot be taken back; therefore, don't publish sensitive qualifications or personal data without a deliberate choice.

## What does verifiable mean?

A title, image, and issue date are not cryptographic proof on their own. The current app credential structure is not a complete W3C Verifiable Credentials implementation. Checking signatures, external proof formats, and revocation lists requires additional protocols.

## If a credential is incorrect

Contact the issuer regarding the content. ROUT can restrict public visibility, but does not decide whether a training course is officially recognized. Never use a badge as the sole proof for access, payments, or legal authorizations.
