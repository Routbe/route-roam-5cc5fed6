- Agent API validation failures go through `agentValidationError` (diagnostics.ts): path, rejected value and an RFC 6902 fix per issue. Why: agents must self-correct without guessing, and echoed values stay truncated.
- Unclaimed agent designs and login-app specs are sealed at rest (`agent-draft-seal.ts`): AES-256-GCM under a random data key wrapped by HKDF keys from the `rsk_` key, claim token and claim code; stored as `{ "$sealed": … }` inside the existing db/0202 columns and opened only in memory during agent requests or the claim. Why: the database holds no readable design before a human owns it, without a schema change.
